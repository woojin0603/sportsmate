# 휴대폰 인증 — 공모전 시연과 실제 SMS 전환

회원가입은 이메일 인증과 휴대폰 인증을 모두 요구합니다. 기본 `local` 프로필은 SMS를 보내지 않고, 서버에서 발급한 랜덤 6자리 인증번호를 화면에 표시합니다. 이는 흐름 시연용이며 실제 전화번호 소유를 증명하지 않습니다. 이메일도 기본 로컬 모드에서는 실제 발송 없이 화면의 테스트 링크로 인증합니다. SMTP 설정 없이 가입 전체를 시연할 수 있습니다. [이메일 인증 안내](EMAIL_VERIFICATION.md)를 참고하세요.

## 로컬 시연

1. Java 17 이상에서 프로젝트 루트의 `./gradlew.bat bootRun`을 실행합니다.
2. `frontend`에서 `npm ci`, `npm run dev`를 실행하고 `http://127.0.0.1:5173`에 접속합니다. Spring만으로 실행하려면 `npm run build:spring` 후 백엔드를 재시작하고 `http://127.0.0.1:8080`에 접속합니다.
3. 회원가입에서 이메일 인증을 완료하고 `010`으로 시작하는 휴대폰 번호 11자리를 입력합니다.
4. **휴대폰 인증번호 받기**를 누릅니다. **실제 문자는 발송되지 않습니다** 안내와 테스트용 인증번호가 표시됩니다.
5. 표시된 번호를 직접 입력하고 **인증번호 확인**을 누른 뒤 회원가입을 완료합니다.

인증번호를 틀리게 입력하거나, 번호를 바꾸거나, 3분이 지난 뒤 확인하는 경우도 시험할 수 있습니다. 테스트 횟수 제한도 실제로 적용됩니다. 이미 인증한 번호를 변경하면 다시 인증해야 합니다. 로그인/회원가입 화면을 전환하면 휴대폰 인증을 다시 진행해야 합니다.

## 구현과 보호 장치

- `POST /api/users/phone/send`: `phoneNumber`를 받아 요청 토큰, 만료 시각, 재발송 대기 초를 반환합니다. 모의 모드에서만 `mock=true`, `developmentCode`가 반환됩니다. 응답은 `Cache-Control: no-store`입니다.
- `POST /api/users/phone/verify`: `phoneNumber`, `requestToken`, `code`를 검증하고 가입용 `verificationToken`을 반환합니다.
- `POST /api/users/signup`: 기존 항목 외에 `phoneRequestToken`, `phoneVerificationToken`이 필수입니다. 전화번호가 인증한 번호와 같아야 합니다.
- 변경 요청에는 기존 CSRF 쿠키/헤더가 필요합니다. 인증 API는 로그인 전 이용 가능합니다.
- 인증번호: `SecureRandom`으로 생성, BCrypt 해시만 저장, 유효시간 3분, 오입력 5회 제한. 실패 횟수는 오류 응답에도 DB에 반영합니다.
- 가입용 증명: 랜덤 토큰의 SHA-256 해시만 저장, 인증 완료 후 10분 유효, 가입 트랜잭션에서 한 번만 소모합니다. 이메일 검증이나 회원 저장이 실패하면 소모도 롤백됩니다.
- 재발송: 번호별 60초 간격, 최근 24시간 5회. 이전 인증번호와 가입용 증명은 무효화합니다.
- 요청 IP별 최근 1시간 10회. 전체 발송 시도는 기본 UTC 날짜별 100회(`SMS_DAILY_LIMIT`)입니다. DB 잠금으로 여러 요청의 동시 통과를 방지하고 재시작 후에도 횟수를 유지합니다.
- 발송 실패도 한도에 포함하며 자동 재시도하지 않습니다. 발송 응답을 받기 전에 서버가 중단되는 예외까지 엄밀하게 과금 제어하려면 공급자 한도와 멱등성/발송 대기열을 추가해야 합니다.
- 인증번호, 가입 토큰을 로그에 쓰지 않습니다. 발송 요청이 들어오면 24시간이 지난 인증 행을 정리합니다. 요청이 없으면 정리되지 않으므로 운영에는 별도 주기 정리 작업을 구성하세요.
- 번호는 국내 `010` 휴대폰만 지원합니다. 해외 번호, 명의자 본인확인, 1인 1계정 판별은 구현 범위가 아닙니다. 같은 전화번호의 복수 계정 제한도 현재 없습니다.

## 모의 모드 차단

기본 설정은 `SMS_MODE=disabled`, `application-local.yml`만 `mock`을 기본으로 사용합니다. 모의 모드는 모든 활성 프로필이 `local` 또는 `test`이고 서버 주소가 `127.0.0.1` 또는 `::1`일 때만 시작됩니다. `local,production` 같은 혼합 프로필, 외부 바인딩 주소, 실제 공급자 없이 `live`를 지정하면 시작에 실패합니다.

로컬 서버를 공개 터널이나 리버스 프록시로 외부에 노출하지 마세요. 루프백 바인딩만으로 공개 터널까지 감지할 수는 없습니다. 공모전 공개 배포는 실제 SMS를 연결하거나, 시연을 별도 비공개 로컬 환경에서 진행하세요.

모의 인증 기록은 실제 발송 모드에서 사용할 수 없습니다. 이미 만들어진 시연 회원 자체를 운영 회원으로 바꾸는 기능은 없으므로 운영 DB는 시연 DB와 분리합니다.

## 실제 SMS 공급자로 전환

1. SMS 공급자 계정과 발신번호를 준비하고 비밀키를 서버 환경변수/비밀 저장소에 설정합니다. React 코드나 Git에는 넣지 않습니다.
2. `member/sms/SmsSender.java`를 구현하는 Spring 빈을 **`liveSmsSender`**라는 이름으로 등록합니다. `send(phoneNumber, code)`에서 공급자 API를 호출하고 실패/거절/타임아웃은 예외로 반환합니다. 성공한 척 반환하거나 코드/비밀키를 로그에 남기지 않습니다.
3. `SMS_MODE=live`로 실행합니다. 화면, 인증번호 검증, 회원가입 API는 변경하지 않습니다. 실제 모드 응답에는 `developmentCode` 필드가 없습니다.
4. 운영 HTTPS 주소, DB 스키마, 발송량 한도를 구성합니다. `phone_verifications`, `sms_budget` 테이블이 추가되며, 기본 `validate` 환경에서는 배포 전에 스키마 마이그레이션이 필요합니다. 로컬은 `ddl-auto=update`로 생성됩니다.
5. 프록시를 사용한다면 직접 접근을 차단하고 신뢰할 프록시만 전달 헤더를 설정하게 구성합니다. IP 제한은 서버가 인식한 `remoteAddr`를 사용합니다. 공유 IP 사용자는 제한을 함께 받습니다.
6. 공급자 측 발송/비용 상한, API 타임아웃, 발송 국가 제한, 남용 탐지 및 필요 시 CAPTCHA를 구성합니다. 이 프로젝트의 DB 잠금은 소규모 시연용 처리량에 맞춘 것으로 대규모 서비스에서는 발송 대기열과 공유 제한 저장소를 검토하세요.
7. 실제 기기로 수신, 오입력, 만료, 재발송, 발송 실패, 가입 완료까지 확인합니다. 현재 구현은 실문자 발송을 수행하지 않았습니다.

## 자동 검증

프로젝트 루트에서 `./gradlew.bat test`, `frontend`에서 `npm run build`를 실행합니다. 전화 인증 테스트는 별도 메모리 H2 DB를 사용하며 실제 문자/이메일은 보내지 않습니다. 정상 인증, 잘못된 번호/토큰, 만료, 실패 횟수 유지, 재발송 무효화, 발송 한도, 동시 사용, 가입 트랜잭션 롤백, 모의 모드 제한을 검증합니다.
