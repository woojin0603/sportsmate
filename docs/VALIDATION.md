**Gradle 작업 제한:** 이 Codex Windows 실행 환경에서는 `gradlew.bat test`와 `compileJava`가 Java 컴파일러의 JAR 파일 시스템 정리 단계에서 `AccessDeniedException`으로 끝납니다. 작은 독립 Java 파일은 컴파일되지만, 의존성 JAR 하나를 classpath에 추가하면 같은 오류가 재현됩니다. 애플리케이션 클래스는 오류가 발생하기 전에 생성되어 실제 서버 기동과 HTTP 검증에 사용했습니다. 일반 Windows/IntelliJ 환경에서 Gradle 작업이 성공하는지는 아직 검증되지 않았습니다.
# 공공 프로그램 파일·신청 기능 추가 검증 (2026-09-13)

- 제공된 899,600,716바이트 JSON을 한 줄씩 분석했습니다. 총 396,693건이고 강좌 기간·요일·시간·모집 정원·가격 필드가 있습니다. 실시간 잔여석, 접수 상태, 기관 예약 API 필드는 없습니다.
- 실제 파일의 2026년 9월 강좌 2건을 H2에 적재하고 `GET /api/programs`의 기간·정원·기관 URL을 확인했습니다. 같은 파일을 다시 적재해 프로그램 수가 유지되는 것도 확인했습니다.
- 시설 좌표도 실제 파일에서 적재해 `GET /api/facilities/{id}`의 위도·경도를 확인했습니다. 파일에서 종료되지 않은 36,832행을 매핑 검사한 결과, 식별자 기준 고유 프로그램은 12,716건, 동일 매핑 중복 행은 24,116건이며 유효성 오류는 없었습니다. 처음 식별자에서 가격·정원 등이 다른 행 2,257건이 충돌하는 것을 발견해 해당 필드를 식별자에 포함했고, 최종 매핑에서 충돌이 없음을 확인했습니다.
- 회원가입·로그인 후 공공 강좌 신청은 `REQUESTED`, 중복 신청은 409, 내 신청 조회·취소·재신청은 성공했습니다. 종료된 2026년 7월 강좌 신청은 409, 공공 강좌에 임의의 시각을 보내면 400을 확인했습니다.
- 기존 `scripts/smoke.ps1` 회귀 검사도 통과했습니다. Python 수집기 문법 검사도 통과했습니다.
- 이 Codex Windows 환경의 `gradlew.bat compileJava --offline --no-daemon`은 기존과 같은 JAR 접근 `AccessDeniedException`으로 끝났습니다. 변경된 클래스 파일은 생성되었으며 그 클래스와 H2 서버로 위 HTTP 검증을 진행했습니다. 일반 Windows/IntelliJ Gradle 전체 빌드의 성공 여부는 아직 확인하지 못했습니다.

## 로컬 데모 데이터 검증

- `local` 프로필의 H2 자동 데이터 생성 후 시설 3건, 프로그램 2건, 공지 1건, 질문 1건, 30세 추천 운동 1건을 HTTP로 확인했습니다.
- 데모 계정 로그인과 초기 `REQUESTED` 신청 조회를 확인했습니다. 정원 1명인 자체 예약 프로그램에서 첫 예약 `CONFIRMED`, 두 번째 회원의 같은 시간 예약 409, 취소 후 재예약 `CONFIRMED`를 확인했습니다.
- 이 Codex 샌드박스의 JAR 접근 오류 때문에 Gradle은 완료되지 않았습니다. UTF-8·`-parameters`를 지정한 수동 Java 컴파일에서 클래스가 생성되었고, 해당 클래스로 서버를 기동해 위 HTTP 검증을 수행했습니다. 사용자는 앞서 IntelliJ에서 기존 프로젝트가 정상 실행된다고 확인했습니다. 이번 변경의 IntelliJ 재빌드는 아직 확인하지 못했습니다.
